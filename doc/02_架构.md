# 02 · 架构

> 完整原始分析见 `03_架构分析_原始立体声工程.md`；本文为当前工程的架构概览。

## 整体数据流

```
INMP441 ──I²S──> RP2040 PIO (i2s_in_slave) ──DMA 双缓冲──> rec_buffer 环形缓冲
                                                                   │
                                                            audio_task (main loop)
                                                                   │
                                                          rec_take() 打包 24-bit
                                                                   │
                                                    tud_audio_write_support_ff()
                                                                   │
                                                          TinyUSB UAC2 IN 端点 ──> 主机
```

## 模块划分

| 文件 | 职责 |
|---|---|
| `src/main.c` | 入口：系统时钟(132 MHz)、stdio uart 初始化、TinyUSB 初始化、`rec_init()`、superloop（`tud_task` / `led_blinking_task` / `audio_task`）、UAC2 控制请求回调（静音/音量/采样率） |
| `src/i2s.c` / `src/i2s.h` | I²S：PIO 状态机装载（`i2s_out_master` 产生 BCK/LRCLK、`i2s_in_slave` 读 SD）、时钟分频计算、DMA 双缓冲（链式 TCB） |
| `src/i2s.pio` | PIO 汇编：`i2s_sck`、`i2s_out_master`、`i2s_in_slave`、`i2s_bidi_slave` |
| `src/rec_buffer.c/.h` | 环形缓冲（`audio_buffers`），`rec_init()`、`audio_data_ready()`、`rec_take()` 把样本打包成 USB 用的 24-bit 字节流 |
| `src/usb_descriptors.c` | USB 设备/配置/字符串描述符（UAC2 麦克风描述符、设备名与厂商名） |
| `src/tusb_config.h` | TinyUSB 配置：UAC2 功能、采样率、通道数、端点大小、FIFO 等 |
| `src/led.c/.h` + `src/ws2812.pio` | WS2812 状态灯（GP16），指示枚举/静音 |

## 关键机制

- **I²S 时钟**：`i2s_out_master` 由 PIO 产生 BCK/LRCLK（主模式），`i2s_in_slave` 读 SD；两者共用时钟引脚，故 PIO 引脚必须满足 `clock_pin_base == din_pin + 1`。
- **DMA 双缓冲**：两组链式 TCB，在中断里判断 DMA 当前读哪块，从而处理刚完成的那块（`dma_i2s_in_handler`）。
- **环形缓冲**：4 个缓冲槽（`USB_AUDIO_BUFFERS`），`process_audio` 写入、`rec_take` 读出。
- **USB 打包**：每帧 2 声道 × 3 字节 = 6 字节；每毫秒 48 帧 → 288 字节/包。
- **UAC2**：描述符声明 2 声道；主机设置 alt interface 后开始等时 IN 传输。

## 单声道适配（参考实现在 `assets/reference/pico_mono_mic/`）

`rec_take()` 改为只取左声道（I²S 缓冲中偶数字），并复制到 L 与 R 两个位置，USB 仍按 2 声道输出（L==R）。这样不必改 UAC2 描述符，最稳妥。

## 构建架构

- 根 `CMakeLists.txt` 引用 `src/` 下的源文件与 `.pio`，由 SDK 的 `pico_generate_pio_header` 在构建时生成 `*.pio.h`。
- `pico_sdk_import.cmake` 引入 SDK（`PICO_SDK_PATH`）。
- `pioasm` / `picotool` 由 CMake 的 `find_package(pioasm/picotool CONFIG)` 定位到 2.1.1 预编译工具。
