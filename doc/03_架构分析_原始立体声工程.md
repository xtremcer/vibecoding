# 项目分析报告：RP2040 立体声 USB 麦克风（UAC2）

> 分析对象：`example/stereo_mic-master_mod/`
> 分析维度：整体架构、模块划分、技术栈、依赖关系、关键配置、核心代码逻辑、耦合点、移植/改造改动点

---

## 1. 项目概览

这是一个**裸机（无 RTOS）的嵌入式固件项目**，把两个 INMP441 MEMS 麦克风采集到的音频通过 **I2S（PIO + DMA）** 采集，再封装成 **USB Audio Class 2.0（UAC2）** 设备，作为“立体声麦克风”被电脑识别。

| 项 | 内容 |
|---|---|
| 目标芯片 | Raspberry Pi RP2040（项目用 RP2040 Zero 板，CMake 中 `PICO_BOARD=pico`） |
| 功能 | 双通道（左/右）48kHz / 24-bit PCM 麦克风 → USB 音频输入设备 |
| 硬件接口 | I2S（INMP441 ×2，共享数据线，靠 LRCLK 时分复用）+ WS2812 状态灯 |
| 软件栈 | Pico SDK 2.1.1 + TinyUSB（UAC2 device）+ PIO 状态机 |
| 运行模型 | 单线程 superloop（`while(1)` 轮询），无操作系统 |
| 构建系统 | CMake + Ninja + arm-none-eabi-gcc 14_2_Rel1 |
| 许可证 | 源码文件各自 GPL-3.0（i2s.*）/ MIT（tusb_config、usb_descriptors、ws2812）/ 仓库根 `LICENSE` |

### 数据流向

```
INMP441 L/R (I2S)  ──BCK/LRCLK/SD──▶  PIO(i2s_in_slave) ──DMA双缓冲──▶ rec_buffer 环形缓冲
                                                                           │
                                                       main.audio_task 轮询 │
                                                                           ▼
                                              rec_take(): 32bit→24bit 打包 ──▶ TinyUSB UAC2 IN EP
                                                                                          │
                                                                                          ▼
                                                                              USB Host (电脑麦克风)
WS2812 LED(GP16) ◀── main.led_blinking_task (挂载/挂起/静音状态指示)
```

## 2. 技术栈与依赖关系

### 2.1 硬依赖（必须存在且版本敏感）
- **Raspberry Pi Pico SDK 2.1.1**：提供 `pico_stdlib`、`hardware_pio`、`hardware_dma`、`hardware_clocks` 等 HAL。通过 `pico_sdk_import.cmake` 从 `PICO_SDK_PATH` 引入。
- **TinyUSB（随 SDK 捆绑）**：实现 UAC2 device 类。`tusb_config.h` 中开启 `CFG_TUD_AUDIO=1`。
  - ⚠️ **关键补丁依赖**：`README.md` 明确要求打 TinyUSB PR #2937（UAC2 支持相关）。**库存 Pico SDK 2.1.1 可能不含该补丁**，移植前必须确认 SDK 内 `tinyusb` 子模块是否已包含该修复；否则 UAC2 枚举/音频流会失败。
- **ARM GCC 工具链 14_2_Rel1** + **CMake 3.31.5** + **Ninja 1.12.1** + **picotool 2.1.1 / openocd**：均来自 `~/.pico-sdk`（见 `.vscode/settings.json` 环境变量），属开发机本地依赖，不随仓库走。

### 2.2 软依赖 / 隐含约定
- **系统时钟 132 MHz**：`main.c` 中 `set_sys_clock_khz(132000, true)` 覆盖默认 125 MHz。该值是为了让 I2S 的 BCK/SCK 分频得到**精确整数比**（详见 §5.1）。改板/改晶振时必须重算。
- **无 RTOS、无 lwIP、无 FreeRTOS**：纯裸机。
- **CMakeLists 中链接了 `hardware_i2c` 与 `pico_rand`，但代码中并未使用**——属冗余依赖，可在移植时清理。

## 5. 核心代码逻辑

### 5.1 I2S 时钟与同步（最关键的时序部分）
- `i2s.h` 的 `i2s_config` 字段顺序：
  `{ fs, sck_mult, bit_depth, sck_pin, dout_pin, din_pin, clock_pin_base, sck_enable }`
- `rec_buffer.c` 中实际应用配置：
  ```c
  { 48000, 256, 32, 10, 6, 7, 8, false }
  ```
  含义：采样率 48k；SCK 倍频 256；位深 32；SCK 引脚 GP10（**未启用**）；DOUT GP6（麦克风输入，未用）；**DIN(SD)=GP7**；**BCLK=GP8、LRCLK=GP9**（clock_pin_base=8，占 8、9）；`sck_enable=false`（不输出系统主时钟）。
- `calc_clocks()` 用 `clk_sys`（132MHz）反推各 PIO 分频整数/小数，使 BCK（=fs×bit_depth×2=3.072MHz）与 SCK（=fs×sck_mult=12.288MHz）成**整数倍比**（此处比值为 4）。`i2s_sync_program_init()` 内 `validate_sck_bck_sync()` 会在 `sck_enable=true` 时校验该比值，否则跳过（本工程因关闭 SCK 而跳过，但 IN_SLAVE SM 仍以 SCK 分频运行以保证 ≥4×BCK 采样）。

### 5.2 DMA 双缓冲机制
- `dma_double_buffer_init()` 申请 4 个 DMA 通道（IN/OUT 各一个 data + 一个 ctrl），利用**链式 TCB + ring 缓冲**实现乒乓双缓冲。
- `in_ctrl_blocks[0/1]` 指向 `input_buffer` 的前/后半区；IN 数据通道由 PIO RX FIFO 触发（DREQ）。
- **IN 数据通道完成中断**（`DMA_IRQ_0`）触发 `dma_i2s_in_handler()`：根据当前 `read_addr` 判断刚填满的是前/后半区，调用 `process_audio()` 把 96 个样本（48 帧 L+R）拷入 `audio_buffers` 环形队列，并 `audio_buffer_items++`。

### 5.3 音频流路径（main ↔ rec_buffer ↔ USB）
- `main.audio_task()`：当 `audio_data_ready()` 为真，计算音量 `vol=(volume[0]*volume[1])/255`，调用 `rec_take(is_muted(), vol)` 得到 288 字节缓冲（96 样本 × 3 字节，L/R 交错 24-bit），再 `tud_audio_write_support_ff(0, buf, 288)` 提交给 USB。
- `rec_take()`：从环形队列取**最旧**一块；逐样本 `(buf[i] >> 8)` 取高 24 位 → 3 字节小端写入 `usb_buffer`；`audio_buffer_items--`；静音或空时返回全零缓冲。
- `AUDIO_SAMPLE_RATE/1000*3*2 = 48*3*2 = 288` 字节/毫秒，与 USB 等时传输节奏一致。

### 5.4 UAC2 控制请求
- `tud_audio_get/set_req_entity_cb` 处理 Feature Unit(ID=2) 的 **Mute / Volume** 与 Clock Source(ID=4) 的 **采样率/时钟有效** 等控制。
- `tud_audio_get_req_entity_cb` 处理 Input Terminal(ID=1) 连接器等只读请求。
- EP/Interface 层的 set/get 回调目前返回 `false`（未实现）。
- 端点回调 `tud_audio_tx_done_*_cb` 仅占位返回 `true`（本工程数据由 I2S 时钟驱动，非回调驱动）。

### 5.5 LED 状态机
- `blink_interval_ms`：`250ms`(未挂载)/`1000ms`(已挂载)/`2500ms`(挂起)，由 `tud_mount/umount/suspend/resume_cb` 切换。
- 静音时红灯亮（`r=120`），否则蓝灯呼吸（`b=140` 闪烁）。

## 6. 耦合点分析（移植前必须理清）

1. **引脚定义分散且需与 README 对齐**
   - 真实引脚表（README）：`SD=GP07, WS(LRCLK)=GP09, SCK(BCLK)=GP08`，L/R 选择脚接 GND(左)/3V3(右)。
   - 代码：`rec_buffer.c` 的 `my_i2s_config`（din=7, clock_pin_base=8 → BCK/LRCLK=8/9）、`led.c` 的 `WS2812_PIN=16`。
   - GP6（dout，未用）、GP10（sck_pin，因 `sck_enable=false` 未用）——保留但当前无效。
   - **两路麦克风靠同一 SD 线 + LRCLK 时分复用**实现立体声，硬件接法不能错。

2. **采样率 48000 在至少 4 处硬编码且必须同步**：
   - `rec_buffer.c`：`SAMPLE_RATE` 宏、`my_i2s_config.fs`
   - `tusb_config.h`：`CFG_TUD_AUDIO_FUNC_1_SAMPLE_RATE`
   - `main.c`：`AUDIO_SAMPLE_RATE`（取自 tusb_config）
   - 端点包大小 `CFG_TUD_AUDIO_EP_SZ_IN` 由上述推导，改动任一处都要全量核对。

3. **缓冲区大小强耦合采样率**：
   - `i2s.h`：`AUDIO_BUFFER_FRAMES=48` → `STEREO_BUFFER_SIZE=96`
   - `rec_buffer.c`：`USB_AUDIO_BUFFER_LEN=2*48000/1000=96`，`USB_AUDIO_BUFFERS=4`
   - 改采样率/帧数时必须同步这些宏，否则 DMA 长度与 USB 提交长度错位。

4. **`i2s_config_default`（i2s.c 中 `sck_enable=true`）与应用配置（`rec_buffer.c` 中 `false`）不一致**——默认配置未被应用使用，易误导移植者。

5. **PIO 资源划分**：I2S 用 `pio1`（2 个 SM：IN_SLAVE、OUT_MASTER），LED 用 `pio0`（1 个 SM）。RP2040 共 2×PIO×4SM；后续加 PIO 功能需注意资源争用。

6. **`i2s.pio.h` 不在仓库**：由 `pico_generate_pio_header()` 构建时生成，`i2s.c` 直接 `#include "i2s.pio.h"`。首次构建必须先跑 CMake configure 生成该头；`ws2812.pio.h` 则已提交。

## 8. 已知问题与风险

1. **音量增益未实现**：如上 §7.9，软件音量形同虚设，仅静音可用。
2. **首帧可能损坏**：`i2s.pio` 注释明确“第一个采样字可能损坏”（可能从 L 帧中途开始），工程未对此做丢弃/对齐处理；若首包异常可在此补偿。
3. **无溢出保护**：`process_audio()` 在 `audio_buffer_items < USB_AUDIO_BUFFERS` 时才写入，缓冲区满则**丢弃**该 1ms 数据（不覆盖），长时间主机停采可能丢数据但不会导致越界，属安全降级。
4. **`i2s_config_default` 与应用配置脱节**：移植者若误用默认配置（含 SCK 输出、不同引脚）会接错线。
5. **耦合脆弱**：采样率/缓冲尺寸散布多文件，任何单点修改若不全局同步即产生隐性错位（缓冲区长度≠USB 提交长度）。

## 9. 移植建议顺序（落地路线）

1. 确认目标 SDK 已含 **TinyUSB PR #2937**；否则先打补丁或换版本。
2. 调整 `CMakeLists.txt` 的 `PICO_BOARD` 与 `main.c` 系统时钟（按新板晶振重算分频）。
3. 按新板引脚/接法改写 `rec_buffer.c` 的 `my_i2s_config` 与 `led.c` 的 `WS2812_PIN`。
4. 若改采样率/位深：统一修改 §6.2、§6.3 全部宏，并重算包大小。
5. 清理/保留 `stdio` 串口、`VID/PID`、字符串。
6. 首次构建确保 `i2s.pio.h` 生成成功；烧录后用电脑验证麦克风枚举与录音。
7. （可选）修复音量增益、首帧丢弃等 §8 问题。
